# Бот для продажи гайда «ИИ без тёмного леса» (ЮKassa)

Telegram-бот, который принимает оплату через ЮKassa и сразу после подтверждения платежа присылает покупателю PDF с персональным водяным знаком.

## Как это работает

```
Пользователь → /start (по ссылке из TikTok, YouTube, VK…)
            → «Купить гайд — 990 ₽»
            → бот создаёт заказ и платёж в ЮKassa, даёт кнопку «Оплатить»
            → пользователь платит картой, СБП, SberPay, T-Pay или ЮMoney
            → ЮKassa присылает уведомление (/pay/notify)
            → бот перепроверяет платёж через API ЮKassa и фиксирует оплату
            → бот присылает PDF, а вам — сообщение о продаже
            → «Вернуться в магазин» на странице ЮKassa ведёт обратно в бота
```

## Защита оплаты

| Угроза | Что делает бот |
|---|---|
| Поддельное уведомление «оплачено» | Уведомлению не верит: берёт из него только ID платежа и запрашивает платёж через API ЮKassa. Гайд — только если API подтвердил `succeeded` и `paid=true` |
| Уведомление с чужого адреса | Отклоняется (403): принимаются только адреса ЮKassa, подставной `X-Forwarded-For` не помогает |
| Подмена суммы, валюты, магазина | Сумма и валюта сверяются с заказом, магазин — с `YOOKASSA_SHOP_ID`, метаданные — с номером заказа и покупателем. Несовпадение — заказ уходит на проверку, вам приходит тревога |
| Тестовая карта в боевом режиме | Тестовые платежи в боевом режиме не засчитываются; ключ `test_…` без `PAYMENTS_TEST_MODE=true` бот не примет |
| Многократные нажатия «Купить» / несколько вкладок | У покупателя одна живая ссылка: перед созданием новой бот спрашивает ЮKassa о прежней |
| Повторная оплата (две вкладки, старая ссылка) | Засчитывается один платёж, лишний автоматически возвращается (ключ идемпотентности не даст вернуть дважды) |
| Обрыв связи при создании платежа | Ключ идемпотентности = номер заказа: повтор не создаёт второй платёж |
| Повторные уведомления, гонки | Гайд выдаётся ровно один раз: оплата и выдача фиксируются атомарно в базе |
| ЮKassa недоступна | Бот отвечает 503, ЮKassa повторяет уведомление; фоновая проверка спрашивает статус сама |
| Уведомление потерялось | Фоновая проверка находит оплату (до 3 суток), кнопка «Я оплатил» и возврат со страницы оплаты спрашивают ЮKassa напрямую |
| Telegram недоступен / бот заблокирован | Оплата фиксируется, гайд отправляется повторно сутки, а при следующем /start — сразу |
| Возврат после покупки | Заказ помечается возвращённым, не считается продажей, гайд по «Мои покупки» больше не выдаётся |

Что ещё умеет бот:

- Приветствие, «Что внутри?», «Поддержка», **«🔒 Конфиденциальность»** — политика конфиденциальности прямо в чате (кнопка и /privacy).
- Описание бота с ценой, ФИО и ИНН продавца выставляется автоматически.
- Страница публичной оферты `https://ваш-адрес/offer`.
- Персональный водяной знак в PDF; «Мои покупки» и /my — получить файл повторно.
- Защита от флуда, работа только в личных сообщениях, понятный ответ при любой ошибке.
- Метки источников трафика и статистика; ежедневная копия базы в `data/backups/`.
- Режим витрины: без ключей ЮKassa бот работает, но вместо оплаты пишет «Приём оплаты подключается».
- Команды для вас: /stats, /grant, /check.

## Установка на VPS

Нужен сервер с **Ubuntu 22.04/24.04 или Debian 12**, доступ по SSH под root (или пользователем с sudo). Свободные порты 80 и 443.

> **Сам гайд (`data/guide.pdf`) в репозитории не хранится** — репозиторий публичный. PDF загружается на сервер отдельно.

### 1. Скачайте код на сервер

```powershell
ssh root@IP_СЕРВЕРА
```
```bash
apt-get update && apt-get install -y git
cd /root && git clone https://github.com/bug1vuge/ai-bot.git guide-bot && cd guide-bot
```

Вместо `git clone` можно загрузить полный архив `guide-bot.zip` (в нём уже есть гайд и библиотеки для установки без интернета) и распаковать его: `unzip -o guide-bot.zip`.

### 2. Положите гайд

Загрузите PDF в `/root/guide-bot/data/guide.pdf` — через FileZilla или с компьютера:

```powershell
scp "путь\к\гайду.pdf" root@IP_СЕРВЕРА:/root/guide-bot/data/guide.pdf
```

При повторной установке шаг можно пропустить: гайд уже лежит в `/opt/guide-bot/data/`.

### 3. Запустите установку

```bash
sudo bash deploy/install.sh
```

Скрипт сам:
- установит Python, шрифты и веб-сервер Caddy;
- спросит токен бота, ваш ID, ник поддержки, ФИО, ИНН, e-mail, shopId и секретный ключ ЮKassa (любой пункт можно пропустить Enter'ом и заполнить потом);
- установит библиотеки (из папки `wheels` полного архива или из интернета);
- настроит автозапуск бота (systemd) и HTTPS-адрес вида `https://1-2-3-4.sslip.io` для уведомлений об оплате;
- в конце покажет адрес для HTTP-уведомлений, который нужно вписать в кабинете ЮKassa.

Если у вас есть свой домен (A-запись указывает на IP сервера), укажите его: `sudo bash deploy/install.sh pay.mysite.ru`.

**Если на сервере уже есть другой проект** (сайт, CRM и т.п.) — ничего страшного:
- бот ставится в отдельную папку `/opt/guide-bot` и работает от отдельного пользователя;
- если порты 80/443 уже занимает **nginx**, скрипт не трогает существующие сайты: он добавляет отдельный файл `/etc/nginx/conf.d/guide-bot.conf` только для адреса бота и получает для него сертификат через certbot. Если nginx не примет настройки, файл удаляется, и всё остаётся как было;
- внутренний порт бота выбирается автоматически (8080 или следующий свободный), чтобы не мешать другим программам;
- свой домен в этом случае указывайте только **новый** (например, поддомен `pay.mysite.ru`), а не домен существующего сайта. Проще всего запустить скрипт без домена — будет адрес вида `1-2-3-4.sslip.io`.

> **Важно:** перед запуском на сервере остановите бота на своём компьютере (закройте окно). Два бота с одним токеном мешают друг другу.

### 4. Если сервер не видит Telegram

Если в конце установки появилось предупреждение «Сервер не может напрямую подключиться к api.telegram.org» (так бывает на российских VPS), боту нужен прокси:

```bash
nano /opt/guide-bot/.env        # строка TELEGRAM_PROXY=socks5://логин:пароль@адрес:порт
systemctl restart guide-bot
```

### Обновление бота

```bash
cd /root/guide-bot && git pull && sudo bash deploy/install.sh ВАШ-ДОМЕН
```

Настройки (`.env`), гайд и база покупок сохранятся. Домен указывайте тот же, что и при установке (без домена — адрес `sslip.io`).

### Полезные команды

| Что | Команда |
|---|---|
| Журнал бота в реальном времени | `journalctl -u guide-bot -f` |
| Последние 50 строк журнала | `journalctl -u guide-bot -n 50 --no-pager` |
| Перезапуск | `systemctl restart guide-bot` |
| Остановка | `systemctl stop guide-bot` |
| Настройки | `nano /opt/guide-bot/.env` (после правки — перезапуск) |
| Проверка HTTPS | `curl https://ВАШ-АДРЕС/health` (ответ `ok`) |
| Копии базы покупок | делаются сами раз в сутки: `ls /opt/guide-bot/data/backups/` |

## Настройка ЮKassa

1. Кабинет ЮKassa → **Интеграция → Ключи API**: скопируйте `shopId` и выпустите секретный ключ (`live_…`).
2. Кабинет ЮKassa → **Интеграция → HTTP-уведомления**: URL `https://ВАШ-АДРЕС/pay/notify`, события `payment.succeeded`, `payment.canceled`, `payment.waiting_for_capture`, `refund.succeeded`. Адрес бот пишет в журнал и присылает вам при запуске.
3. В `/opt/guide-bot/.env` на сервере:

```
YOOKASSA_SHOP_ID=123456
YOOKASSA_SECRET_KEY=live_...
PAYMENTS_TEST_MODE=false
```

4. `systemctl restart guide-bot` — бот пришлёт сообщение с магазином, режимом и адресом уведомлений.
5. Купите гайд сами: проверьте, что файл пришёл, а оплата появилась в кабинете ЮKassa.

**Тестовый магазин.** Для проверки без денег создайте тестовый магазин в ЮKassa, впишите его `shopId` и ключ `test_…` и поставьте `PAYMENTS_TEST_MODE=true`. Ссылку на оплату тогда получают только администраторы (`ADMIN_IDS`): тестовой картой иначе мог бы «купить» кто угодно. Тестовые оплаты не входят в выручку.

**Чеки.** Самозанятому в кабинете ЮKassa нужно подключить передачу чеков в «Мой налог» (раздел о самозанятых) — тогда ЮKassa регистрирует доход автоматически.

**Если оплата есть в кабинете, а гайд не пришёл** — `/check номер_заказа`: бот запросит платёж в ЮKassa и, если он оплачен, выдаст гайд. Номер заказа виден в описании платежа в кабинете: «… (заказ 1793005224-123456789)».

Секретный ключ и токен никому не отправляйте. Если они где-то засветились — выпустите новый ключ в кабинете ЮKassa или токен в @BotFather и обновите `.env`.

## Публичная оферта

Бот сам показывает оферту по адресу `https://ваш-адрес/offer` и даёт на неё ссылку на экране оплаты и в «Поддержке».

- **Реквизиты** (ФИО, ИНН, e-mail, ник поддержки) берутся из `.env`: строки `SELLER_NAME`, `SELLER_INN`, `SELLER_EMAIL`, `SUPPORT_USERNAME`. После правки — `systemctl restart guide-bot`.
- **Текст оферты** — файл `/opt/guide-bot/data/offer.md`. Правьте его через `nano` или FileZilla; изменения видны сразу, перезапуск не нужен. Значения в фигурных скобках (`{seller_name}`, `{seller_inn}`, `{price}`, `{bot}`, `{support}`, `{seller_email}`, `{date}`) бот подставляет сам — не удаляйте их. Дата редакции — дата последнего изменения файла.
- Если какое-то поле не заполнено, на странице будет «[НЕ ЗАПОЛНЕНО]», а в журнале бота — предупреждение.
- Хотите хранить оферту в другом месте — укажите ссылку в `OFFER_URL`.

Шаблон оферты — не юридическая консультация; при сомнениях покажите его юристу.

## Ссылки с метками для контент-фермы

```
https://t.me/ваш_бот?start=tiktok
https://t.me/ваш_бот?start=yt_shorts
https://t.me/ваш_бот?start=vk_video_15
```

Метка сохраняется при первом заходе. В /stats видно, сколько людей пришло с каждой метки и сколько купили. Латиница, цифры, `_` и `-`, до 64 символов.

## Команды администратора

| Команда | Что делает |
|---|---|
| `/stats` | Пользователи, продажи, выручка (без тестовых оплат), конверсия, источники, невыданные заказы |
| `/grant 123456789` | Выдать гайд пользователю по ID (пользователь должен хотя бы раз запустить бота) |
| `/check 1793005224-123` | Запросить заказ в ЮKassa; если оплачен, а гайд не выдан — выдать |

## Запуск на своём компьютере (Windows)

Для проверки без сервера: дважды щёлкните `start_windows.bat` (нужен Python 3.12–3.14). Без внешнего HTTPS-адреса уведомления ЮKassa до компьютера не дойдут, поэтому приём оплаты на компьютере отключён (режим витрины). Для настоящей работы используйте VPS.

## Частые проблемы

| Симптом | Решение |
|---|---|
| «Не заполнен BOT_TOKEN» | Впишите токен в `.env`, перезапустите |
| «Не удалось связаться с Telegram» | Укажите `TELEGRAM_PROXY` в `.env` |
| «Приём оплаты подключается» | Режим витрины: в `.env` нет `YOOKASSA_SHOP_ID`/`YOOKASSA_SECRET_KEY`/`PUBLIC_URL`, или включён `PAYMENTS_TEST_MODE` |
| «Не удалось создать ссылку на оплату» | Неверный shopId/ключ (в журнале — ошибка 401) или ЮKassa недоступна. Проверьте ключи в `.env` |
| Оплатил, гайд не пришёл | Проверьте URL HTTP-уведомлений в кабинете ЮKassa и `journalctl -u guide-bot -n 50`. Для покупателя — `/check номер_заказа` |
| В журнале «Нет связи с Telegram» | Бот ждёт связь и сам переподключается; оплаты при этом принимаются. Если долго — укажите `TELEGRAM_PROXY` |
| «Платёж прошёл, но бот не выдал гайд» | Платёж не прошёл проверку (сумма, магазин, метаданные). Проверьте его в кабинете ЮKassa; выдайте гайд через `/grant` или верните деньги |
| «На адрес уведомлений пришёл запрос не от ЮKassa» | Кто-то стучится на адрес уведомлений — запрос отклонён, делать ничего не нужно |
| `curl .../health` не отвечает | `systemctl status caddy`, порты 80/443 открыты у хостера (в панели VPS) |

## Разработка

```bash
pip install -r requirements-dev.txt
ruff check .
python -m pytest -q
```

Тестам настоящий гайд не нужен: они собирают небольшой PDF сами. Те же проверки запускаются в GitHub Actions при каждом push.

Коммиты оформляются по [Conventional Commits](https://www.conventionalcommits.org/ru/): `fix(payments): …`, `feat(bot): …`, `docs: …`.
