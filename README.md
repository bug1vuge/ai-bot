# Бот для продажи гайда «ИИ без тёмного леса» (Prodamus)

Telegram-бот, который принимает оплату через Prodamus и сразу после оплаты присылает покупателю PDF с персональным водяным знаком.

## Как это работает

```
Пользователь → /start (по ссылке из TikTok, YouTube, VK…)
            → «Купить гайд — 990 ₽»
            → бот создаёт заказ и даёт кнопку «Оплатить» (платёжная страница Prodamus)
            → пользователь платит картой, СБП и т.д.
            → Prodamus присылает боту уведомление (/pay/notify), бот проверяет подпись и сумму
            → бот присылает PDF, а вам — сообщение о продаже
            → кнопка возврата на странице Prodamus ведёт обратно в бота
```

Что умеет бот:

- Приветствие, описание гайда, кнопки «Купить», «Что внутри?», «Поддержка» (с реквизитами продавца и офертой).
- Описание бота с ценой, ФИО и ИНН продавца выставляется автоматически (этого требует проверка Prodamus).
- Своя страница публичной оферты `https://ваш-адрес/offer`: ФИО, ИНН, цена, ник бота и контакты подставляются из `.env`.
- Повторное нажатие «Купить» не плодит новые заказы; номера заказов не повторяются даже после переустановки бота или потери базы.
- Защита от подделки: уведомление принимается только с верной подписью (секретный ключ, HMAC-SHA256), сумма сверяется с заказом.
- Гайд выдаётся ровно один раз, даже если уведомление пришло несколько раз.
- Уведомление подтверждается сразу, а гайд отправляется в фоне: медленный Telegram не мешает приёму оплаты.
- Если Telegram недоступен, бот продолжает принимать оплаты и отправит гайд, как только связь появится.
- Если файл не отправился (например, покупатель заблокировал бота), бот повторяет выдачу с нарастающей паузой в течение суток, а при следующем /start отдаёт гайд сразу. Вас он предупредит один раз.
- Покупатель, вернувшийся со страницы оплаты раньше уведомления, видит «Проверяю оплату…», а не «оплата не поступила».
- Повторную оплату тем же покупателем бот замечает и просит вас сделать возврат.
- Отклонённые уведомления сохраняются в `data/rejected_notifications/`, а вам приходит тревожное сообщение.
- Ежедневная резервная копия базы в `data/backups/` (хранятся последние 14).
- Персональный водяной знак на каждой странице PDF (ник, ID, дата); экземпляр собирается один раз и дальше пересылается мгновенно.
- «Мои покупки» и /my — получить файл повторно.
- Защита от флуда, работа только в личных сообщениях, понятный ответ при любой ошибке.
- Метки источников трафика и статистика по ним.
- Режим витрины: без данных Prodamus бот работает, но вместо оплаты пишет «Приём оплаты подключается».
- Команды для вас: /stats, /grant, /check, /paid.

## Установка на VPS

Нужен сервер с **Ubuntu 22.04/24.04 или Debian 12**, доступ по SSH под root (или пользователем с sudo). Свободные порты 80 и 443.

> **Сам гайд (`data/guide.pdf`) в репозитории не хранится** — репозиторий публичный. PDF загружается на сервер отдельно.

### 1. Скачайте код на сервер

```powershell
ssh root@IP_СЕРВЕРА
```
```bash
apt-get update && apt-get install -y git
cd /root && git clone https://github.com/bug1vuge/ai-bot.git guide-bot && cd guide-bot
```

Вместо `git clone` можно загрузить полный архив `guide-bot.zip` (в нём уже есть гайд и библиотеки для установки без интернета) и распаковать его: `unzip -o guide-bot.zip`.

### 2. Положите гайд

Загрузите PDF в `/root/guide-bot/data/guide.pdf` — через FileZilla или с компьютера:

```powershell
scp "путь\к\гайду.pdf" root@IP_СЕРВЕРА:/root/guide-bot/data/guide.pdf
```

При повторной установке шаг можно пропустить: гайд уже лежит в `/opt/guide-bot/data/`.

### 3. Запустите установку

```bash
sudo bash deploy/install.sh
```

Скрипт сам:
- установит Python, шрифты и веб-сервер Caddy;
- спросит токен бота, ваш ID, ник поддержки, ФИО, ИНН, e-mail, адрес платёжной страницы и секретный ключ Prodamus (любой пункт можно пропустить Enter'ом и заполнить потом);
- установит библиотеки (из папки `wheels` полного архива или из интернета);
- настроит автозапуск бота (systemd) и HTTPS-адрес вида `https://1-2-3-4.sslip.io` для уведомлений об оплате;
- в конце покажет адрес для уведомлений, который нужно вписать в Prodamus.

Если у вас есть свой домен (A-запись указывает на IP сервера), укажите его: `sudo bash deploy/install.sh pay.mysite.ru`.

**Если на сервере уже есть другой проект** (сайт, CRM и т.п.) — ничего страшного:
- бот ставится в отдельную папку `/opt/guide-bot` и работает от отдельного пользователя;
- если порты 80/443 уже занимает **nginx**, скрипт не трогает существующие сайты: он добавляет отдельный файл `/etc/nginx/conf.d/guide-bot.conf` только для адреса бота и получает для него сертификат через certbot. Если nginx не примет настройки, файл удаляется, и всё остаётся как было;
- внутренний порт бота выбирается автоматически (8080 или следующий свободный), чтобы не мешать другим программам;
- свой домен в этом случае указывайте только **новый** (например, поддомен `pay.mysite.ru`), а не домен существующего сайта. Проще всего запустить скрипт без домена — будет адрес вида `1-2-3-4.sslip.io`.

> **Важно:** перед запуском на сервере остановите бота на своём компьютере (закройте окно). Два бота с одним токеном мешают друг другу.

### 4. Если сервер не видит Telegram

Если в конце установки появилось предупреждение «Сервер не может напрямую подключиться к api.telegram.org» (так бывает на российских VPS), боту нужен прокси:

```bash
nano /opt/guide-bot/.env        # строка TELEGRAM_PROXY=socks5://логин:пароль@адрес:порт
systemctl restart guide-bot
```

### Обновление бота

```bash
cd /root/guide-bot && git pull && sudo bash deploy/install.sh ВАШ-ДОМЕН
```

Настройки (`.env`), гайд и база покупок сохранятся. Домен указывайте тот же, что и при установке (без домена — адрес `sslip.io`).

### Полезные команды

| Что | Команда |
|---|---|
| Журнал бота в реальном времени | `journalctl -u guide-bot -f` |
| Последние 50 строк журнала | `journalctl -u guide-bot -n 50 --no-pager` |
| Перезапуск | `systemctl restart guide-bot` |
| Остановка | `systemctl stop guide-bot` |
| Настройки | `nano /opt/guide-bot/.env` (после правки — перезапуск) |
| Проверка HTTPS | `curl https://ВАШ-АДРЕС/health` (ответ `ok`) |
| Копии базы покупок | делаются сами раз в сутки: `ls /opt/guide-bot/data/backups/` |

## Настройка Prodamus

1. В личном кабинете Prodamus откройте настройки платёжной страницы и найдите **секретный ключ** и поле **URL для уведомлений** (раздел уведомлений / интеграций).
2. В поле URL для уведомлений впишите `https://ВАШ-АДРЕС/pay/notify` — адрес бот пишет в журнал и присылает вам при запуске.
3. В `/opt/guide-bot/.env` на сервере:

```
PRODAMUS_URL=https://ваше-имя.payform.ru
PRODAMUS_SECRET=секретный_ключ_платёжной_страницы
PAYMENTS_TEST_MODE=false
```

4. `systemctl restart guide-bot` — бот пришлёт вам сообщение с режимом работы и адресом для уведомлений.
5. Купите гайд сами (можно временно поставить `PRICE_RUB=10` или включить `PAYMENTS_TEST_MODE=true`, чтобы ссылку видели только вы): проверьте, что файл пришёл, а в кабинете Prodamus и в «Мой налог» появились оплата и чек.

`PAYMENTS_TEST_MODE=true` — ссылку на оплату получают только администраторы (`ADMIN_IDS`), остальные видят «Приём оплаты подключается». Удобно, пока идёт проверка платёжной страницы.

Если оплата есть в кабинете Prodamus, а гайд не пришёл (уведомление не дошло), — `/paid номер_заказа`: бот отметит заказ оплаченным и отправит гайд. Номер заказа виден в кабинете Prodamus (номер заказа магазина, вида `1793005224-123456789`).

Секретный ключ и токен никому не отправляйте. Если они где-то засветились — смените их в кабинете Prodamus или @BotFather и обновите `.env`.

### Проверка канала продаж в Prodamus

Prodamus проверяет, что в «шапке» канала продаж указаны ФИО, ИНН и цены. Для бота это **описание** (видно до нажатия «Старт») и **короткое описание** в профиле — бот выставляет их сам при каждом запуске из `SELLER_NAME`, `SELLER_INN` и `PRICE_RUB`. ФИО указывайте точно как в паспорте и в «Мой налог».

## Публичная оферта

Бот сам показывает оферту по адресу `https://ваш-адрес/offer` и даёт на неё ссылку на экране оплаты и в «Поддержке».

- **Реквизиты** (ФИО, ИНН, e-mail, ник поддержки) берутся из `.env`: строки `SELLER_NAME`, `SELLER_INN`, `SELLER_EMAIL`, `SUPPORT_USERNAME`. После правки — `systemctl restart guide-bot`.
- **Текст оферты** — файл `/opt/guide-bot/data/offer.md`. Правьте его через `nano` или FileZilla; изменения видны сразу, перезапуск не нужен. Значения в фигурных скобках (`{seller_name}`, `{seller_inn}`, `{price}`, `{bot}`, `{support}`, `{seller_email}`, `{date}`) бот подставляет сам — не удаляйте их. Дата редакции — дата последнего изменения файла.
- Если какое-то поле не заполнено, на странице будет «[НЕ ЗАПОЛНЕНО]», а в журнале бота — предупреждение.
- Хотите хранить оферту в другом месте — укажите ссылку в `OFFER_URL`.

Шаблон оферты — не юридическая консультация; при сомнениях покажите его юристу.

## Ссылки с метками для контент-фермы

```
https://t.me/ваш_бот?start=tiktok
https://t.me/ваш_бот?start=yt_shorts
https://t.me/ваш_бот?start=vk_video_15
```

Метка сохраняется при первом заходе. В /stats видно, сколько людей пришло с каждой метки и сколько купили. Латиница, цифры, `_` и `-`, до 64 символов.

## Команды администратора

| Команда | Что делает |
|---|---|
| `/stats` | Пользователи, продажи, выручка (без тестовых оплат), конверсия, источники, невыданные заказы |
| `/grant 123456789` | Выдать гайд пользователю по ID (пользователь должен хотя бы раз запустить бота) |
| `/check 1793005224-123` | Статус заказа; если оплачен, но гайд не выдан — выдать |
| `/paid 1793005224-123` | Оплата есть в кабинете Prodamus, а уведомление не дошло — отметить оплаченным и выдать гайд |

## Как что-то поменять

| Что | Где |
|---|---|
| Цена | `PRICE_RUB` в `.env` |
| Тексты сообщений и кнопок | `bot/texts.py` |
| PDF | замените `data/guide.pdf` |
| Водяной знак | `WATERMARK` в `.env`, текст — `WATERMARK` в `bot/texts.py` |

## Запуск на своём компьютере (Windows)

Для проверки без сервера: дважды щёлкните `start_windows.bat` (нужен Python 3.12–3.14). Без внешнего HTTPS-адреса уведомления Prodamus до компьютера не дойдут, поэтому приём оплаты на компьютере отключён (режим витрины). Для настоящей работы используйте VPS.

## Частые проблемы

| Симптом | Решение |
|---|---|
| «Не заполнен BOT_TOKEN» | Впишите токен в `.env`, перезапустите |
| «Не удалось связаться с Telegram» | Укажите `TELEGRAM_PROXY` в `.env` |
| «Приём оплаты подключается» | Режим витрины: в `.env` нет `PRODAMUS_URL`/`PRODAMUS_SECRET`/`PUBLIC_URL`, или включён `PAYMENTS_TEST_MODE` |
| Сообщение «уведомление, которое бот не смог проверить» | `PRODAMUS_SECRET` не совпадает с секретным ключом платёжной страницы. Исправьте и выдайте гайд через `/paid` |
| Оплатил, гайд не пришёл | Проверьте URL для уведомлений в кабинете Prodamus и `journalctl -u guide-bot -n 50`. Для покупателя — `/paid номер_заказа` |
| В журнале «Нет связи с Telegram» | Бот ждёт связь и сам переподключается; оплаты при этом принимаются. Если долго — укажите `TELEGRAM_PROXY` |
| Сообщение «Prodamus прислал уведомление об оплате, но бот не выдал гайд» | Деньги получены, но сумма не совпала или заказ неизвестен — проверьте платёж в кабинете и выдайте гайд через `/grant` |
| `curl .../health` не отвечает | `systemctl status caddy`, порты 80/443 открыты у хостера (в панели VPS) |

## Разработка

```bash
pip install -r requirements-dev.txt
ruff check .
python -m pytest -q
```

Тестам настоящий гайд не нужен: они собирают небольшой PDF сами. Те же проверки запускаются в GitHub Actions при каждом push.

Коммиты оформляются по [Conventional Commits](https://www.conventionalcommits.org/ru/): `fix(payments): …`, `feat(bot): …`, `docs: …`.
